Where it opens

A permanent row in the sidebar, a ? button in the chat header, and F1 anywhere. Dialog-level links can open the exact article later.

How it reads

Same surfaces, type, and lime accent as the cockpit. Screenshots are the real UI, with numbered callouts that match the steps.

Where it lives

Markdown in docs/guide, images beside it. The renderer imports both at build time, so the guide works with no network.

Two other shapes

Both are useful later. Neither replaces the full reader for onboarding, browsing, and search.

Option B

Contextual help drawer

A narrow panel that opens the article for the current screen. Good for a quick fix while the chat stays visible; weak for reading, browsing, and first-run onboarding.

Phase 2. Best as deep links from dialogs, not the main entry.

Option C

Separate reader window

Open the guide in a second Electron window or the default browser. Good on a second monitor and for printing; it adds a second window to manage and a parallel UI shell to maintain.

Useful later for “Open in browser”; not the default.

04 / Build plan

Small enough to ship in one pass

The reader is one component, one IPC-free content import, and a screenshot script. The writing is the real work.

  1. Phase 1

    Guide and reader

    Write 12 articles in docs/guide, capture 9 screens from demo data, build the Help Center, and wire the sidebar row plus F1.

    2–3 days · full-screen reader, search, figures
  2. Phase 2

    Contextual links

    Add “Read the guide” links to Settings, Routines, and the agent editor. Open the exact article and remember the last topic between launches.

    1–2 days · deep links, last-read state
  3. Phase 3

    Keep it honest

    A Playwright script rebuilds the screenshots from a seeded demo profile. A docs check in local-diagnostics fails when a tool or settings section loses its article.

    ongoing · screenshots and coverage checks
